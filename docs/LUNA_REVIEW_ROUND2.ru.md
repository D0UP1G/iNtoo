### Обновление A00: реальная сборка Quickshell на Gentoo

Получен результат попытки собрать `gui-apps/quickshell-0.3.1::guru`:
фаза compile завершилась с ошибкой Ninja при `-j4`. В приложенном фрагменте
отсутствует первичная строка компилятора (`fatal error`, `Killed signal` либо
конкретный C++ error), а самого `/var/tmp/portage/.../temp/build.log` в текущем
workspace нет. Видимые предупреждение `control reaches end of non-void function`
в `active_connection.cpp:65` и сообщение про нераспознанный
`-Wno-vla-cxx-extension` сами по себе не доказывают причину остановки.

В доступной среде Portage задан `MAKEOPTS="-j4"`, оперативная память около
3,2 GiB, swap отсутствует. Это делает нехватку памяти правдоподобной причиной,
но без первичного сообщения компилятора остаётся гипотезой. До успешной сборки
и проверки импортов A00 остаётся открытым; результат установки USE-флагов не
подтверждает, что Quickshell собрался с нужными модулями.

Для диагностического повтора ограничить параллельность только этой командой:

```bash
MAKEOPTS="-j1" emerge --verbose --update --changed-use --ask \
  '=gui-apps/quickshell-0.3.1::guru'
```

Если сборка снова падает, сохранить строки первичной ошибки из полного лога:

```bash
rg -n -B 8 -A 8 'fatal error:|Killed signal|error:|compilation terminated|FAILED:' \
  /var/tmp/portage/gui-apps/quickshell-0.3.1/temp/build.log
```

`Killed signal terminated program cc1plus` подтвердит давление памяти; другой
диагноз потребует исправления конкретной причины из соседних строк лога.

Все конфигурации для R05, входные конфигурации R06 и конфигурация R08 проверены
настоящим установленным `niri validate`. Git и операции файловой системы
используют настоящие инструменты во временных каталогах. Lifecycle-команды
замокированы. В R06 наблюдатель записывает граф, который получает настоящий
валидатор; в R09 намеренно введён `OSError` при публикации второго файла.
Это проверка отказоустойчивости, а не наблюдавшаяся ошибка реального диска.

Полная QML-оболочка ii/Waffle/Iris не загружается: `SettingsOverlay unavailable`
из-за отсутствия `Quickshell.Hyprland`. Проверка импортов выявляет десять
отсутствующих модулей, включая сервисные модули Quickshell и `QtMultimedia`.
Успешные Portage/systemd/OpenRC проверки с заглушками не подтверждают исправление
этой установленной среды. Изолированные QML-проверки выбора конфигурации проходят.

ShellCheck отсутствует. Local suite также предупреждает о недокументированном
IPC `mascotMood` и пропускает terminal palette без Python-окружения iNtoo.
Review-набор пока не включён ни в `make test-local`, ни в `make test-audit`;
его нужно запускать отдельной командой.

## R08 · P0 · Откат перезаписывает другой файл через заменённый родительский каталог

Место: [niri-snapshot.py](../sdata/lib/niri-snapshot.py),
`preflight_restore`, строка 116; `restore`, строка 126.

Воспроизведение:

1. Root подключает `/tmp/fixture/external/startup.kdl` с `echo original`.
2. Создать снимок. Manifest сохраняет разрешённый абсолютный путь файла.
3. Переименовать каталог `external` в `saved-external`; на прежнем месте создать
   ссылку `external -> unrelated`.
4. В `unrelated/startup.kdl` положить другое пользовательское содержимое.
5. Выполнить настоящий `restore_snapshot` с заглушкой lifecycle.

Откат возвращает успех и заменяет `unrelated/startup.kdl` на `echo original`.
Preflight проверяет только последний компонент `target.is_symlink()`;
ссылку в родительском пути он не замечает. Создание временного файла и
`os.replace` проходят через перенаправленный каталог. Резервная копия другого
файла удаляется после успешной операции.

Задание Luna: проверять идентичность разрешённого целевого пути и всех каталогов
до остановки оболочки и повторно при публикации. Запретить изменившееся
перенаправление; при работе через directory fd исключить повторное следование
новым ссылкам. Ошибка должна сохранять чужой файл, текущую конфигурацию и состояние
сервиса. Документировать разрешённые внешние пути и политику изменения ссылок.

Приёмка: `test_r08_restore_refuses_redirected_external_parent` проходит;
сохранить старые тесты корректного восстановления внешних файлов и ссылок.

## R07 · P1 · Миграция скрывает настройки за legacy-ссылкой и удаляет её при отказе

Место: [config-dir-compat.sh](../sdata/lib/config-dir-compat.sh),
`inir_config_compat_apply`, строки 12–23 и 59–61.

Первый сценарий: существует только `illogical-impulse -> /tmp/fixture/user-config`
с пользовательским `config.json`. Resolver выбирает этот файл. Миграция 019
удаляет ссылку, создаёт пустой `inir` и новый alias; возвращает 0. Старый файл
физически сохраняется снаружи, но CLI/QML больше его не видят. Конфигурация может
быть заново создана с defaults.

Второй сценарий: canonical-путь занят обычным файлом. Миграция возвращает отказ,
но прежняя legacy-ссылка уже удалена. Ошибка в предварительных условиях меняет
пользовательскую конфигурацию до выполнения самой миграции.

Задание Luna: сначала проверить весь исходный layout. Для внешней legacy-ссылки
либо безопасно перенести/скопировать данные и сохранить исходный alias для
восстановления, либо явно отказать, сохранив прежнюю доступную конфигурацию.
Не удалять ссылку до подготовки замены; возвращать исходный layout при любом
отказе. Проверить относительные ссылки и ошибки move/copy/link. Так как ID 019
и 044 уже могли быть отмечены, ремонт затронутых установок должен учитывать
реальное состояние и при необходимости иметь следующий migration ID.

Приёмка: оба `test_r07_*` проходят; прежние R01 и A01 остаются зелёными.

## R05 · P1 · Новый KDL-разбор не соответствует активному графу Niri

Места: [niri_kdl.py](../scripts/lib/niri_kdl.py), `lex`, строка 102,
`nodes`, строка 174, `string_arguments`, строка 204;
[session-startup.py](../scripts/lib/session-startup.py), `config_files`, строка 55;
[niri-snapshot.py](../sdata/lib/niri-snapshot.py), `include_graph`, строка 23.

Настоящий Niri принимает следующие команды, но startup status возвращает false:

```kdl
"spawn-at-startup" "inir" "run" "--session"
spawn-at-startup /* multiline
 comment */ "inir" "run" "--session"
spawn-at-startup \ // continuation comment
 "inir" "run" "--session"
```

Имена узлов в кавычках пропускаются, перевод строки внутри блочного комментария
ошибочно завершает узел, а продолжение с комментарием не распознаётся.
Disable оставляет такие команды, enable может добавить вторую.

Для отключённого поддерева результат обратный:

```kdl
/- unused {
    spawn-at-startup "inir" "run" "--session"
}
```

Status возвращает true, а enable вырезает сохранённую внутри команду. Include
в таком поддереве тоже обходится: отключённая ссылка на каталог заставляет
создание обязательного снимка завершиться отказом, хотя конфигурация валидна.

Отдельно снимок пропускает активный внешний файл для двух допустимых форм:

```kdl
"include" "/tmp/fixture/active.kdl"
include /- "missing.kdl" "/tmp/fixture/active.kdl"
```

Во втором случае обработчик берёт отключённый аргумент вместо активного.
Создание снимка и откат возвращают 0, но внешнее содержимое не восстанавливается.
Startup и snapshots используют один lexer, однако выбирают include-аргументы
по-разному: все строковые токены против первого строкового токена.

Задание Luna: разбирать активные узлы и аргументы по правилам KDL, включая
quoted names, slash-dash для узлов/поддеревьев/аргументов, комментарии как
пробелы и допустимые продолжения. Учитывать контекст дерева. Использовать один
контракт выбора позиционного include-пути в обоих потребителях. Сохранять
исходные диапазоны отключённой и посторонней конфигурации. Не считать успешное
`niri validate` доказательством того, что собственный обход увидел тот же граф.

Приёмка: все пять `test_r05_*` проходят; старые R02/A02/A03 сохраняют успех.
В startup-тесте после проверки status предусмотрена проверка disable; сейчас
она не достигается из-за первого нарушенного assertion.

## R06 · P1 · Валидатор читает другой граф, чем тот, который будет опубликован

Место: [session-startup.py](../scripts/lib/session-startup.py),
`_validate_candidate`, строка 102.

При `include "../shared/startup.kdl"` вне каталога Niri исходная конфигурация
валидна. Enable копирует только `niri` в `config/inir-niri-candidate-*/niri`.
Относительный include теперь указывает в отсутствующий соседний `shared`;
валидатор отвергает правильный запрос, startup не обновляется.

При абсолютном внешнем include отказа нет, но изменённый внешний файл
пропускается при staging. В воспроизведении enable переносит команду из внешнего
файла в root. Валидатор видит одновременно новую root-команду и старую внешнюю
команду: две команды вместо одной в окончательно опубликованной конфигурации.
Наблюдатель подтверждает это при настоящем вызове `niri validate`, без подмены
его результата. Аналогично абсолютный include внутреннего файла может читать
живую версию вместо staged-копии.

Задание Luna: staging должен представлять весь активный граф с планируемым
содержимым, сохраняя значение относительных путей или перенаправляя ссылки
только внутри временной копии. Проверять именно будущий граф. Не записывать
во внешние живые файлы при подготовке проверки. Если гарантировать корректный
staging для формы include нельзя, давать явный отказ с причиной.

Приёмка: оба `test_r06_*` проходят. Для приведённых относительного и абсолютного
include допустимы два исхода: корректно проверить и опубликовать ровно один
startup-узел либо явно отказать с понятной причиной, оставив все файлы без
изменений. Тихий пропуск внешнего файла и отказ из-за пути, сломанного только
временным staging, приёмкой не считаются. Добавить варианты абсолютного
внутреннего include, root-ссылки и ссылок на каталоги; убедиться, что live
конфигурация не меняется до завершения валидации.

Текущие тесты считают безопасным отказом только сообщение, которое указывает
на неподдержанный или небезопасный include. Ошибка Niri о пропавшем временном
пути не считается таким отказом; она подтверждает дефект staging.

## R09 · P1 · Отказ публикации второго startup-файла удаляет прежний автозапуск

Место: [session-startup.py](../scripts/lib/session-startup.py),
`sync`, цикл публикации на строке 208.

Root содержит работающую startup-команду и подключает `50-startup.kdl`.
Enable планирует удалить команду из root и добавить её в подключённый файл.
После успешной записи root в тесте введён отказ записи второго файла.
Sync выбрасывает `OSError`, но первый файл уже изменён; startup-команды больше
нет ни в одном из файлов. `atomic_write` защищает отдельный файл, а не весь набор.

Задание Luna: подготовить все записи и резервные копии до публикации.
При отказе любой замены восстановить уже заменённые файлы; не возвращать успех
при неполном восстановлении. Сохранять permissions и не менять ссылки или
посторонние команды. Предусмотреть явное сообщение, если восстановление тоже
не удалось, и оставить доступные резервные копии.

Приёмка: `test_r09_failed_startup_publish_restores_previously_written_files`
проходит. Дополнить отказом rollback-записи и проверкой сохраняемых backup-файлов.
