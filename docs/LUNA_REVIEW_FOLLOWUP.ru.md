## R04 · P0 · Realign уничтожает игнорируемые пользовательские данные

Места: [snapshots.sh](../sdata/lib/snapshots.sh), `repo_worktree_is_clean`
(строка 504), `realign_repo_to_remote` (строка 554);
[setup](../setup), ветка восстановления после переписывания upstream
(вызов около строки 2533).

Воспроизведение:

1. В старом опубликованном коммите `.gitignore` исключает `/user-data`.
2. В новом переписанном upstream-коммите `user-data` становится отслеживаемым.
3. Пользователь имеет свой игнорируемый `user-data`; статус Git чистый.
4. История origin в reflog подтверждает force-push. Настоящая
   `is_upstream_rewrite_divergence main` возвращает успех.
5. Настоящая `realign_repo_to_remote main` возвращает 0, но содержимое
   `private local data` заменяется на `upstream data`.

Причина: `git status` не показывает игнорируемые данные, а перед
`git reset --hard origin/main` нет проверки коллизий с целевым деревом.
Созданный recovery ref сохраняет старый коммит, но не содержимое игнорируемого
файла. Путь может запускаться автоматически при обнаруженном force-push,
без явного `--realign`.

Задание Luna: вынести общую проверку коллизий из rollback и использовать её
перед realign. Учитывать совпадение пути и коллизии файл/каталог, включая
вложенные игнорируемые файлы. Ошибка получения статуса или списка файлов
должна запрещать операцию. До отказа не изменять HEAD, ветку и пользовательские
файлы; setup должен передать отказ через код возврата и update-status.

Приёмка: `test_r04_realign_preserves_ignored_user_data` проходит; дополнить
проверками коллизий файл/каталог и вызова через setup. Существующая безопасная
realign-регрессия в локальном наборе продолжает проходить.

## R02 · P1 · Обработчик startup не распознаёт допустимые команды KDL

Место: [session-startup.py](../scripts/lib/session-startup.py),
`QUOTED`, `SPAWN`, `INCLUDE`, `config_files` и построчная обработка `sync`
(строки 13–15, 125, 142 и 151).

Настоящий Niri принимает все следующие примеры:

```kdl
include r"50-startup.kdl"
```

```kdl
include \
    "50-startup.kdl"
```

```kdl
spawn-at-startup "inir" \
    "run" "--session"
```

```kdl
spawn-at-startup r"inir" "run" "--session"
```

Обработчик не обходит первые два подключения. Для последних двух `status`
возвращает false. `disable` оставляет активную многострочную команду на месте.
При `enable` существующая команда сохраняется и добавляется ещё одна managed
команда; это нарушает управление автозапуском и может порождать лишние старты.

Причина: исправление комментариев оставило разбор через regex отдельных строк
и JSON-декодирование только обычных строк. Это не эквивалентно KDL-узлам.

Задание Luna: разбирать целые активные узлы с сохранением диапазонов исходного
текста, поддержать raw-строки, escape-последовательности и продолжения. Сохранить
учёт вложенных комментариев, отключённых узлов, циклов include и посторонних
команд. Использовать согласованный разбор в status/enable/disable; проверить
кандидат настоящим `niri validate` перед публикацией. Проверить аналогичные
допущения в миграции 018, не считая их отдельной подтверждённой ошибкой.

Приёмка: три `test_r02_*` проходят. Дополнить проверкой двух последовательных
enable, после которых остаётся ровно одна активная команда запуска.

## R03 · P1 · Успешный откат не восстанавливает внешние активные include

Место: [snapshots.sh](../sdata/lib/snapshots.sh), создание снимка Niri
(строки 61–64), восстановление дерева (строки 305–311).

Воспроизведение: root config подключает файл снаружи `$XDG_CONFIG_HOME/niri`
по абсолютному пути либо через символическую ссылку внутри каталога Niri.
Оба случая валидны для установленного Niri. Создать снимок, изменить внешнюю
команду `echo original` на `echo changed`, затем восстановить снимок.
Восстановление возвращает 0, но Niri продолжает читать `echo changed`.

Причина: `rsync -a` сохраняет только дерево Niri, включая сами ссылки;
внешние файлы и содержимое целей ссылок в снимок не попадают. Комментарий
«restores every included startup/rule file» шире фактической гарантии.

Задание Luna: сохранять активный граф include с разрешёнными путями, содержимым
и явным manifest; корректно обрабатывать абсолютные/относительные пути, ссылки,
циклы и повторные подключения. Определить и документировать границу допустимых
внешних путей. Для поддержанных файлов обеспечить восстановление содержимого;
для неподдержанных запрещать создание обязательного снимка с ясной причиной,
чтобы update не публиковал обещание полного отката. Старые снимки без manifest
не должны молча обещать восстановление внешнего графа.

Приёмка для поддерживаемых пользовательских файлов: оба `test_r03_*` проходят.
Дополнить отказом чтения внешнего файла, циклическим графом и старым снимком.
